# Project governance

This is a community-contributed, maintainer-reviewed project. The current maintainer is [corith37](https://github.com/corith37), the repository owner.

- Anyone can report issues, propose improvements, submit pull requests, or maintain an MIT-licensed fork.
- Product and architecture proposals should be discussed publicly in Issues or Discussions. Small, focused fixes can be submitted directly.
- Maintainers review scope, user experience, compatibility, tests, and privacy implications before merging. Passing CI is evidence for review, not an automatic approval.
- Maintainers control repository settings, merges, version tags, and official releases. Release procedure and build scripts are public.
- Contributions remain under the project license with their authorship intact. Third-party components retain their licenses. There is no required contributor license agreement.

Review happens as maintainer availability allows; there is no guaranteed response time or roadmap deadline. If a proposal is declined, the goal is to explain the constraint and leave room for a smaller alternative. Contributors should follow the [Code of Conduct](CODE_OF_CONDUCT.md).

Changes to project direction or contribution policy should be proposed through a public PR so contributors can see and discuss them.
